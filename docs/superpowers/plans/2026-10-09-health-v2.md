# 小兔🐰的健康追蹤表 — 版本2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this approved plan task-by-task. The user approved execution and required the original to be backed up first.

**Goal:** Extend the existing phone diet diary into a daily health tracker without changing its public URL or losing existing diet records.

**Architecture:** Keep the existing nutrition HTML and storage key `ying-diet-v1`. Add additive schema version 2, a pure UMD `health-core.js` for migration/calculations, and `health-ui.js` for stable phone form DOM and monthly review. Develop in `version2/public` before copying tested files to the live source/deploy copies.

**Tech Stack:** Plain HTML/CSS/JavaScript, localStorage, SVG charts, Node built-in test runner, real mobile-viewport browser checks, GitHub Pages.

## Approved design and defaults
- Title and version: 小兔🐰的健康追蹤表 · 版本2.
- Tabs: 健康 (default), 飲食 (all original features), 月回顧, 設定. Recent diet/history remains accessible from monthly review.
- Health: optional weight kg, body fat %, bedtime and wake time (cross-midnight); 8h sleep goal; five 500cc water buttons (2500cc); optional exercise hours one decimal, aerobic/strength multiple selections, quick activity choices and free text; manual green/yellow/red status plus optional tags.
- Exercise frequency: >0 recorded hours counts one session per recorded day; 0 is an explicitly recorded rest day; no forced 1h threshold. Weekly goal 3, Monday–Sunday; show this rule visibly. Blank is not rest. Today's incomplete week is not considered a failed week.
- Body summary: first/last valid measurements and dates; fewer than two => insufficient data; fat change is percentage points, not percent change.
- Month: sleep/water achieved rates over measured days, with missing days shown. Exercise monthly sessions/hours and completed-week goal progress separately. Completed weeks are attributed to the month containing Sunday, and only weeks with an explicit exercise/rest entry enter the rate. All missing weeks appear separately; current week stays in progress.
- Next-month plan/reward are manual text fields and completion/claimed checkboxes, stored by month. Two accessible, responsive body trend charts, no invented/interpolated measurements.
- Quick entry goal ~30 seconds for new health fields, not a guarantee including detailed diet entry.
- Old app migration keeps meals/photos/targets/recent/export metadata and unknown additive fields; snapshot old JSON under a distinct browser key when upgrading, if storage permits. The zip backs up app code, not the user's phone data. No cloud sync.
- Never replace focused inputs while typing; persist valid edits without remounting. Decimal invalid input displays inline error, does not overwrite the previous saved value.
- On storage quota failure, do not silently delete photos. Show a persistent warning and advise exporting data.
